## Context

The current `SmartIMEHost` only supports Chinese input via `librime`. It lacks a mechanism to switch to an English-only mode where keystrokes are passed through or enhanced with English-specific completions. The `IMEInputController` currently routes all events directly to the `ChineseInputEngine`.

## Goals / Non-Goals

**Goals:**
- Implement a `Shift` key (or similar) toggle for switching between Chinese and English modes.
- Create an `EnglishInputEngine` protocol and implementation that handles English typing and completion.
- Integrate the English engine into `IMEInputController` to handle keystrokes when in English mode.
- Support basic word-level English completion using a simple dictionary.

**Non-Goals:**
- Advanced English grammar checking or sentence-level prediction.
- Support for multiple English dictionaries in this milestone.
- Complex mixed-mode (Pinyin + English) in the same composition buffer beyond basic pass-through.

## Decisions

### 1. Unified Engine Protocol
We will refine the engine protocols in `packages/shared-models` to ensure both `ChineseInputEngine` and `EnglishInputEngine` follow a similar pattern for processing keys and returning `InputSessionUpdate`.

### 2. Mode Toggling
The `Shift` key will be used as the primary toggle for switching between Chinese and English. The `IMEInputController` will monitor key events to detect a single `Shift` key press/release without other modifiers or characters to trigger the mode switch.

### 3. English Engine Implementation
The `EnglishInputEngine` will be implemented in `packages/english-engine`. It will maintain its own internal state for the current English "word" being typed and provide completion candidates based on a bundled word list.

The word list holds the 30,000 most frequent lowercase English words from wordfreq 3.1.1, one per line in frequency order, with profanity and slurs removed. It is generated by `scripts/english/build-wordlist.py` and is licensed CC-BY-SA 4.0 (see `packages/english-engine/DATA_LICENSE.md`). `EnglishLexicon` loads it once per process, keeps it alphabetically sorted with each word's frequency rank, and answers prefix queries with a binary search instead of scanning the whole list on every keystroke.

The typed text is always the first candidate, followed by up to eight completions ordered by frequency. `Space` commits the highlighted candidate, or the typed text when nothing is highlighted, so a larger lexicon never silently replaces a finished word with a more frequent completion (for example `cat` with `catch`).

### 4. Candidate UI Re-use
English completion candidates will be displayed using the existing `IMKCandidates` panel. The selection logic (number keys, arrow keys) will remain consistent across modes.

## Risks / Trade-offs

- **[Risk]** Key event leaking when switching modes. → **[Mitigation]** Ensure `IMEInputController` correctly handles the return value of `handle(_:client:)` to swallow the toggle key when used for switching.
- **[Trade-off]** Using a simple word list instead of a sophisticated NLP model. → **[Mitigation]** This keeps the IME lightweight and matches the Phase 1 goals for a fast, predictable experience.
